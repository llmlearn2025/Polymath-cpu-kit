What do these mean?

A pack is a number of experts (small networks, each the size of one of the base model's own experts) placed in a number of the model's layers. Experts per layer is how much the pack can hold at each depth; layers is at how many depths it can act. More of either gives the pack more room for knowledge and makes the file larger, and it needs more training data to fill. Facts and terms usually fit a standard pack. A large body of knowledge, or a pack that teaches a way of writing or reasoning, needs more.

The layers are chosen automatically as a band starting in the middle of the model; to pick them yourself, type them under layers below (for example 18,19,20,21, or all).

The suggestion above comes from the amount of training text and from what the dataset teaches. It is a rule of thumb that has not been measured yet, so treat it as a starting point and compare pack sizes in the Workbench.

The workbench engine is stopped during training and restarted after. The best epoch (lowest loss on the dataset's tests) is kept.

User pack

Your preferences, conventions and projects, baked into a pack. Fill the squares, name the pack, create.
Options
Everything is set automatically and can be changed here. The LLM divides each square into semantic units of about the unit size (by meaning, not by count) and writes one statement per unit; each statement gives 1–3 training items × depth; 3 test probes per square. No limits by default; the plan shows the cost before training, which stops early when it stops improving.
